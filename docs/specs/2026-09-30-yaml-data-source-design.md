# 数据源迁移：Excel → YAML 设计

## 背景与目标

现在 `travel.xlsx` 是唯一可信数据源，生成器每次只发布一个 Sheet。存在以下问题：

- AI 很难可靠地修改 Excel（条件格式、公式、COM 渲染等问题）。
- 历史上的 5 次旅行分别使用三种不同的格式。
- 每次旅行不能独立发布。

本次重构要达到的目标：

1. 每次旅行保存为一个 YAML 文件，成为新的唯一可信数据源。数据模型由 pydantic 严格定义。
2. 5 次历史旅行全部迁移到新格式。
3. 网站改为多旅行结构，包含首页列表、每次旅行的时间轴页和表格视图。
4. CI 先校验再发布，数据不合法时不发布。
5. 迁移完成后从仓库删除 `travel.xlsx`（git 历史中仍可找回）。

修改方式：主要由 AI 修改 YAML，人偶尔在 VS Code 中手改。人查看行程和花销统计通过生成的网页，不再使用 Excel。

## 不在本次范围

- 行程合理性检查（时间冲突、路程来不及、预算超标）
- `.ics` 日历提醒
- `profile.yaml` 偏好档案
- 接入地图、车次等 MCP
- Excel 导出或双向同步
- 跨旅行花销统计（与 AI 预算建议一起放到下一阶段）
- 多币种与汇率换算（金额一律按人民币记录）
- 在 PWA 内直接编辑行程

## 1. 目录与数据模型

### 目录结构

```text
trips/
  2026-summer-yunnan.yaml
  2026-qingming-chengdu-chongqing.yaml
  2025-guoqing-changsha-wuhan.yaml
  2025-summer-yantai-weihai.yaml
schema/
  trip.schema.json        # 由 pydantic 导出，供 VS Code 补全与校验
scripts/
  trip_model.py           # 数据模型、读取与校验（唯一的数据定义）
  generate_site.py        # YAML → 静态网站
  export_schema.py        # 导出 JSON Schema
  migrate_xlsx.py         # 一次性迁移脚本，迁移完成后删除
templates/                # Jinja2 页面模板与共用静态资源
tests/
.vscode/
  extensions.json         # 推荐安装 redhat.vscode-yaml
  settings.json           # 把 trips/*.yaml 关联到 schema
```

- 旅行 id 就是文件名（不含扩展名），同时用作网址路径。文件内不重复写 id。
- 文件名只能由小写字母、数字和 `-` 组成。
- schema 关联通过 `.vscode/settings.json` 中的 `yaml.schemas` 配置，YAML 文件本身不写 `$schema` 注释。

### 示例

```yaml
title: 2026 盛夏 · 上海深圳香港昆明大理轻松旅行计划
start: 2026-08-02
end: 2026-08-08
travelers: 2
notes: 慢节奏原则：每天只安排 1–2 个核心区域
days:
  - date: 2026-08-02
    label: 苏州 → 上海 → 深圳 → 香港
    items:
      - title: 高铁
        type: 交通
        start: "07:28"
        end: "07:59"
        note: G7503 苏州园区 → 上海虹桥
        price: 38
        qty: 2
        booking_at: 2026-08-01
        status: 已购买
        place: 上海虹桥站
```

### 字段

旅行：

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `title` | ✅ | 字符串 | 标题 |
| `start` / `end` | ✅ | 日期 | 旅行起止日期，`end` 不早于 `start` |
| `travelers` | | 正整数 | 人数 |
| `notes` | | 字符串 | 整体说明 |
| `days` | ✅ | 列表 | 至少一天 |

天：

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `date` | ✅ | 日期 | |
| `label` | | 字符串 | 为空时页面显示“8月2日 周日” |
| `items` | ✅ | 列表 | 可以为空列表 |

事项：

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `title` | ✅ | 字符串 | |
| `type` | ✅ | 枚举 | 交通、住宿、游览、餐饮、日常、购物、其他 |
| `start` / `end` | | `"HH:MM"` 字符串 | 必须加引号 |
| `note` | | 字符串 | 路线、车次、地址、营业时间等 |
| `price` | | 非负数 | 单价 |
| `qty` | | 非负数 | 数量 |
| `cost` | | 非负数 | 总价，仅在无法拆成单价 × 数量时使用 |
| `booking_at` | | 日期或日期时间 | 开售或预约时间，格式为 `2026-08-01` 或 `2026-08-02 14:00` |
| `status` | | 枚举 | 默认“无需预订”；其余可选值：待购买、待预约、已购买、已预约、已完成、已取消 |
| `place` | | 字符串 | 地图关键词；为空时页面不显示地图操作 |

事项的消费金额（派生值）：

- 有 `cost` 时取 `cost`；
- 否则 `price` 和 `qty` 都有时，取二者乘积；
- 两个条件都不满足时，视为没有消费。

待办：`status` 为“待购买”或“待预约”的事项。

### 花销统计（派生值）

所有金额均以人民币计，由 `trip_model.py` 统一计算，页面和命令行共用同一套结果：

- 总额；人均（有 `travelers` 时才计算）；
- 每天小计；
- 按类型统计金额与占比；
- 已付：状态为已购买、已预约、已完成的事项；
- 待付：状态为待购买、待预约的事项。

状态为“已取消”的事项不计入任何金额统计。

### VS Code 编辑体验

导出的 JSON Schema 需要包含以下内容，支撑手工编辑：

- 每个字段的中文 `description`，鼠标悬停时显示；
- `type`、`status` 使用 `enum`，可以下拉选择；
- 时间：
  - 在 `examples` 中列出 `00:00` 至 `23:50`、间隔 10 分钟的候选；
  - 用 `pattern` 校验 `HH:MM`，允许手工输入 `19:28` 这类精确时间；
- `defaultSnippets`：提供“新事项”和“新的一天”两个插入模板。

如果 `redhat.vscode-yaml` 不会把 `examples` 显示为下拉候选，改为在 `defaultSnippets` 中提供时间候选。

### 校验规则

以下规则由 pydantic 强制执行：

- 禁止未知字段（`extra="forbid"`）。
- `start` 和 `end` 必须是符合 `HH:MM` 的字符串，读到数字或其他类型一律报错。
- `type` 和 `status` 必须是枚举中的值。
- `cost` 不能与 `price` 或 `qty` 同时出现。
- 每天的 `date` 必须在旅行的 `start` 到 `end` 之间，且严格递增、不能重复。
- 事项的 `end` 可以早于 `start`，表示跨过午夜。
- 字符串字段会去掉首尾空白；去掉后为空的可选字段按“未填写”处理。

YAML 使用 `ruamel.yaml` 以 YAML 1.2 规则读取，避免 YAML 1.1 把 `19:28` 解析成六十进制整数、把 `yes` 或 `no` 解析成布尔值等问题。

## 2. 迁移规则

### 旅行清单

| 来源 Sheet | 目标文件 | 标题 |
| --- | --- | --- |
| 26暑期云南 | `2026-summer-yunnan.yaml` | 沿用 A1 |
| 模板验证-清明重庆（以此为准）+ 26清明重庆成都（用于核对） | `2026-qingming-chengdu-chongqing.yaml` | 沿用 A1 |
| 25国庆长沙武汉 | `2025-guoqing-changsha-wuhan.yaml` | 2025 国庆 · 长沙武汉 |
| 25大电烟台威海 | `2025-summer-yantai-weihai.yaml` | 2025 暑期 · 烟台威海 |
| 验证 | 不迁移 | 这是时间下拉选项的辅助数据 |

### 通用规则

- 以下两类行视为纯占位行，删除：
  - 没有项目名称，且其余单元格只有 `0`、空值、`☐` 或默认值；
  - 新版 Sheet 中只填了日期和类型的行也属于此类。
- 单价和数量都有值时，存为 `price` 和 `qty`。只有消费金额时，存为 `cost`。金额为 0 或空时不存。
- 时间统一转成 `"HH:MM"`。
- 分隔行中日期后面的文字作为当天的 `label`。
- 新版 Sheet 中的 B2、C2 作为旅行的 `start`、`end`，E2 作为 `travelers`，A3 作为 `notes`。

### 旧格式特有规则

- **日期**：从分隔行解析（如“9月30日周六”），年份取 Sheet 名前两位（`25` 即 2025 年）。某行有日期列但为空时，沿用上一行的日期。
- **旅行起止日期**：没有摘要区的旧 Sheet，取第一天和最后一天的日期。
- **类型**：按项目名称中的关键词推断：

  | 关键词 | 类型 |
  | --- | --- |
  | 打车、高铁、飞机、地铁、公交、观光车 | 交通 |
  | 入住、酒店入住、退房、酒店 | 住宿 |
  | 早餐、午饭、午餐、晚饭、晚餐 | 餐饮 |
  | 起床 | 日常 |
  | 其他 | 游览 |

- **状态**：
  - `☑` 映射为“已购买”，游览类映射为“已预约”；
  - `☐` 映射为“无需预订”。
- **抢票时间列**：
  - 真实日期存为 `booking_at`；
  - `done` 丢弃；
  - 其他文字追加到 `note`。
- **地点**：`place` 留空，不按名称猜测。

### 迁移核对

对每次旅行分别核对以下项目，任一项不一致就报错，不写入文件：

- **总消费**：迁移后的总消费必须与 Excel 一致，误差不超过 0.01。比较时双方都要包含“已取消”的事项，不适用统计口径中排除已取消的规则。
  - 新版 Sheet 用 I 列的计算结果求和；
  - 旧版 Sheet 用首行的“总消费”单元格。
- **事项数**：有项目名称的行数必须与迁移后的事项数一致。

清明这次旅行另外输出一份差异清单，交给用户确认：

- 原始版中有、整理版中缺失的事项；
- 两个版本的总消费差额。

清单中的内容不自动合并。

迁移结果需人工抽查：检查类型推断和状态映射是否合理。

## 3. 页面生成与发布

### 网站结构

```text
output/
  index.html                 # 旅行列表首页
  <trip-id>/index.html       # 手机时间轴
  <trip-id>/table.html       # 表格视图
  assets/app.css
  assets/app.js
  icons/
  manifest.webmanifest
  service-worker.js
```

### 首页

- 每次旅行显示一张卡片，内容为标题、日期范围、天数、总消费、待办数和阶段标记。
  - 阶段按访问时的本地日期由前端计算，分为进行中、即将出发和已结束。
- 进行中和即将出发的旅行置顶并突出显示，其余按开始日期倒序排列。
- 首页地址保持不变，已经添加到主屏幕的图标可以继续使用。

### 时间轴页

- 保留现有全部功能：
  - 按天导航，默认定位到当天或最近一天；
  - 标记当前事项和下一事项；
  - 高德、Apple、百度三种地图可选，并记住上次选择；
  - 复制地点和整条事项；
  - 深色模式和离线提示。
- 顶部新增“← 全部旅行”和“表格视图”两个入口。
- 继续满足 iPhone 适配约束：
  - 页面设置 `viewport-fit=cover`，并适配 `env(safe-area-inset-*)`；
  - 触控区域不小于 44px；
  - 不出现横向溢出。

### 表格视图

- 面向桌面浏览和横向打印。
- 列为：日期、时间、类型、项目、备注、消费、开售时间、状态、地点。
- 类型颜色只作用于类型列，状态颜色只作用于状态列，色值沿用现有规则。
- 表头固定，每天有分隔行并显示当日小计。
- 表格末尾显示“花销统计”区块。
- 提供打印样式：横向排版，打印时隐藏导航。

### 花销统计区块

- 时间轴页在顶部摘要下方放一个可折叠的统计区块，默认折叠；表格视图把这个区块放在末尾。
- 内容为总额、人均、按类型统计的金额与占比，以及已付和待付金额。
- 用纯 HTML 和 CSS 的条形图展示类型占比，不引入图表库。

### PWA

- 全站只有一个 manifest 和一个 Service Worker，作用范围是整个站点，预缓存所有页面和资源。
- 缓存版本号取全部生成内容的 hash。
- 缓存策略沿用现有的网络优先、离线回退。
- README 中写到的“新版本刷新提示”和“待办筛选”在现有代码中并未实现。本次不补做，只在文档中删去这两项描述。

### 生成器

- 使用 Jinja2 模板，并开启自动转义；CSS 和 JS 抽成共用静态文件。
- 继续使用现有的 PNG 图标生成逻辑，不引入图像库。
- 运行依赖为 `ruamel.yaml`、`pydantic`（v2）和 `jinja2`，去掉 `openpyxl`。
- 迁移阶段临时需要 `openpyxl`，与迁移脚本一起删除。

### CI

- 触发路径：
  - `trips/**`、`scripts/**`、`templates/**`、`schema/**`、`tests/**`；
  - 依赖文件；
  - 工作流文件本身。
- 执行步骤依次为：安装依赖、`--check` 校验、pytest、生成网站、上传产物，最后按 `DEPLOY_TARGET` 发布。任一步失败都不发布。
- `DEPLOY_TARGET` 的原有逻辑保持不变。

### 文档

- 重写 `CLAUDE.md`：
  - 删除 Excel 模板、条件格式和 COM 相关的约定；
  - 改为 YAML 字段规范、修改流程（改完先运行 `--check`）和发布约定。
- 同步更新 `README.md`。

## 4. 校验与测试

### 命令

| 命令 | 作用 |
| --- | --- |
| `python scripts/generate_site.py` | 校验全部旅行，然后生成到 `output/` |
| `python scripts/generate_site.py --check` | 只校验，不生成；校验通过后输出每次旅行的统计摘要（总额、按类型金额、待办数） |
| `python scripts/export_schema.py` | 导出 `schema/trip.schema.json` |

### 报错

- 错误信息包含文件名、字段路径和原因。例如：`2026-summer-yunnan.yaml: days[1].items[3].status: 无效值 '已买'`。
- 汇总所有文件的全部错误后统一输出。
- 有错误时退出码非 0。
- YAML 语法错误同样按文件汇总报告，包含行号。

### 自动化测试（pytest）

- **模型**：
  - 合法样例能通过校验；
  - 以下每条规则至少有一个反例：未知字段、时间不带引号、非法枚举值、`cost` 与单价或数量同时出现、日期超出范围、日期重复或乱序；
  - 消费金额和待办的派生计算结果正确；
  - 花销统计正确：人均、按类型金额、已付和待付，并且已取消的事项被排除。
- **生成**：用固定样例旅行生成网站，然后检查：
  - 首页卡片数和页面链接；
  - HTML 转义；
  - Service Worker 的缓存清单覆盖所有页面；
  - 生成的 JSON Schema 与模型一致。
- **真实数据**：`trips/` 下的全部文件都能通过校验。

### 视觉验证（人工截图确认）

- iPhone 16（393 × 852）和 iPhone 16 Pro（402 × 874）尺寸下，截图检查首页和时间轴页，浅色、深色模式各一次。

- 写错字段名或枚举值时，会出现红色波浪线。
- “新事项”和“新的一天”两个模板都能插入。

### 发布后验证

- GitHub Actions 运行成功。
